# Файлы для итогового задания

В директории `tests` находятся тесты для проверки API, которое должно быть реализовано в веб-сервере.

Директория `web` содержит файлы фронтенда.

# Планировщик задач:

Веб-приложение для создания и управления задачами с указанием даты выполнения,
комментария и правила повторения

Сервер написан на GO, для хранения данных используется SQLite, Веб интерфейс находится в директории `web`

# Возможности:

- Создание задачи
- Просмотр списка задач
- Поиск задач
- Просмотр отдельной задачи
- Редактирование задачи
- Удаление задачи
- Отметка задачи как выполненной
- Повторение задачи по различным правилам
- HTTP API
- Авторизация с помощью JWT
- Запуск приложения в Docker

# Выполненные задачи со звездочкой:

- Повторение задач по дням недели (w)
- Повторение задач по дням месяца и месяцам (m)
- Спец. значения для последнего (-1) и предпоследнего (-2) дня месяца
- Авторизация с помощью JWT
- Docker-образ приложения

# Запуск локально:

Для запуска необходим установленный GO

Перед запуском можно задать следующие переменные окружения:

- export TODO_PORT=7540
- export TODO_DBFILE=scheduler.db
- export TODO_PASSWORD=your_password

Если переменные не заданы, приложение использует значения по умолчанию, предусмотренные в коде.

Если TODO_PASSWORD не задан, то авторизация отключена

Запуск приложения:

- go run .

После запуска планировщик доступен по адресу:

- http://localhost:7540/

# Запуск тестов:

Перед запуском необходимо убедиться, что сервер не занимает порт `7540` и что переменные окружения (в частности TODO_PASSWORD), заданные в текущей сессии терминала, соответствуют тому, что ожидают тесты
иначе запросы будут падать

Обычный запуск:

- go test ./tests

# Настройка тестов:

Основные настройки находятся в:

- tests/settings.go

При включенной авторизации в переменную `Token` необходимо поместить JWT токен,
полученный через `/api/signin`.

Если авторизация отключена, `Token` можно оставить пустым.

Для проверки расширенных правил `NextDate`:

- var FullNextDate = true
  Для проверки поиска задач:
- var Search = true

# Сборка приложения:

Для обычной сборки:

- go build -o scheduler .

Для запуска приложения в Linux контейнере с Windows:

- GOOS=linux GOARCH=amd64 go build -o scheduler .

# Docker:

Образ собирается многоступенчато - компиляция Go бинарника происходит внутри самого образа.

Для создания Docker образа:

- docker build -t scheduler .

В образ копируются:

- исполняемый файл `scheduler`
- директория `web`

SQLite база данных не копируется напрямую в образ.
Она подключается с хоста при запуске контейнера.

# Запуск Docker контейнера:

Для Git Bash на Windows перед запуском необходимо выполнить:

- export MSYS_NO_PATHCONV=1

Запуск контейнера:

- docker run --rm -p 7540:7540 -v "$(pwd)/data:/data" -e TODO_PASSWORD=your_password scheduler

База данных `scheduler.db` из директории проекта будет доступна внутри контейнера по пути `/data/scheduler.db`.
